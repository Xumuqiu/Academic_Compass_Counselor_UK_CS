# 最终范围与设计取舍

更新2026-10-04。依据：[原提案与导师反馈](https://app.notion.com/p/92e330883cc983d8bf7901ca2e86b62a?pvs=204)和用户后续要求。原记录的凭证待配置、无真实评测等状态已被实际运行替代；历史尝试保留在评测记录。

## 范围

原Navigator设想包括经历收集、项目比较、理由、规划与行动后调整。用户要求独立UK CS Counselor保留从输入到脑暴DOCX的流程，去掉后续学业规划，并以JSON CV为当前测试输入。没有独立成绩单合并、长期档案或三问固定上限。待确认问题是补证据的追问，不是学业规划。

收窄到事实与措辞支持关系，便于检验核心风险。它是原问题的第一阶段，不能声称完成原方案所有功能。学校老师关于专业问题、取舍、限制及跨经历组织的建议启发访谈结构，但不能证明学生已有对应能力。

## 构建与租用

| 层 | 取舍 |
| --- | --- |
| 网页、本地服务、状态、JSON归一化 | 自建；便于控制来源和复现，没有机构级身份或长期存储 |
| 六要素、问题与事实ID | 确定性规则和模板；不是自主LLM规划访谈 |
| 解析、生成、语义核查 | 租用模型；同模型不同调用仍可能共同犯错 |
| 引用、数字、覆盖、收窄准入 | 自建规则；引文存在不代表支持措辞，严格规则也会误拦 |
| 项目与UCAS数据 | 本地来源查找，没有向量RAG，11条项目待核实 |
| 导出与评测 | 自建DOCX、快照、计费、评分汇总；guard verdict不能作为真值 |

原提案DashScope/Qwen plus和flash改为实测OpenRouter/openai/gpt-4.1-mini，没有双模型路由。先前OpenAI401来自供应商误认，路由修复后连接与配对运行成功。API费用采用usage.cost。

## 当前结果与限制

6例成功开发预跑、20例真实配对运行、40份DOCX及单一AI评分已完成。无依据率20.42%降至17.34%，原低于10%目标未达；两组缺口覆盖82.14%、事实保留100%。高分常来自保留学生原话，不证明专业建议质量。20例非独立held-out，无独立人工复核。[质量报告](../eval/OUTPUT_EVALUATION_REPORT.md)。

Guard主要覆盖候选主线与角度，组合叙述仍发布未确认或错误事实。真实使用前需要修事实准入、否定/指令/撤回及最终整包核查。本次保留已评测版本，报告缺陷，优先完成交付说明、报告和视频，不改变口径美化成绩。

原提案无schema的基线没有完整实现；当前两组共享schema、固定问答、解析和候选，只评价guard增量，不证明动态访谈或整体系统收益。主运行USD0.123158，含连接和预跑USD0.1839696；人工时间未测。
