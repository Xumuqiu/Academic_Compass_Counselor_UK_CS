# Project Statement 核对与第二版决策

核对日期：2026-10-04。依据：[Notion 原始 Project Statement、导师反馈及最终交付说明](https://app.notion.com/p/92e330883cc983d8bf7901ca2e86b62a?pvs=204)，当前代码及[真实输出评测](../eval/OUTPUT_EVALUATION_REPORT.md)。原始提案是 formative proposal；导师明确说如何采纳中期反馈由学生决定。以下是项目决策，不能视为成绩保证。

## 决策

**本次作业先冻结已评测的系统版本，完成产品与复现说明、报告和演示，不把第二版作为提交前置条件。** 最终交付说明要求有理由地批判最终结果、透明提交数据与评测、可运行代码和产品文档，没有明确要求开发第二版，也没有将低于10%写成提交的硬性门槛。低于10%仍是本项目承诺的成功目标，当前未达到，必须如实报告，不能事后降低目标。

这不是认定系统无需修复。未经核查的叙述、否定和纠正处理、指令转事实都是实际产品缺陷；真实学生使用前需要修复，并验证最终输出。当前只能作为顾问复核的研究原型展示。此次只补交付文档与复现验证，不更改生产代码、冻结数据、评分规则、原始输出或标注，也不修改 Notion 提案。

## 第二版什么时候必要

如果目标是实现原提案的质量目标，或交付真实顾问使用，第二版有必要：先修叙述的事实准入，再处理否定/计划/指令/撤回，最后核查组合后的完整输出，校准误放与误拦。现有20例只能作为开发回归集；若进一步宣称泛化改进，需另外准备独立数据及外部复核。具体失败位置与改动优先级见评测报告第3、5节。

本次报告的可辩护结论是：在20个作者编写的合成案例上，guard减少部分主线与角度错误，但整体仍未达目标，且核查后的叙述拼接留下主要漏洞。课程交付可以呈现这一发现与限制；不能把它包装为已经可靠解决学生事实支持问题的成品。
