## 2. 评分目标

| 主指标 | 口径 | 目标 |
| --- | --- | --- |
| 无依据论点率 | 已发布原子论点中表述过强、证据不足或与实际记录冲突的数量 / 全部已发布原子论点 | 沿用原提案 **<10%** |
| 缺口覆盖率 | 正确指出的预审具体缺口数 / 顾问应指出且从共同实际输入可发现的缺口数 | 报告实际分子分母；目标尚待确定 |

次要指标包括已支持且有用的事实机会保留率、空输出/拒答率、失败率、引用错误、缺口误报、时延和成本。旧“有用素材≥70%”仅作为历史探索参考。零发布论点的无依据率为N/A，不算0%达标。失败保留在案例分母，未交付的缺口和事实机会不得计命中。

论点需覆盖主线、角度、叙述、使用建议和三问映射，不只计候选 `angle`。原子拆分、重复去重、CV未确认事实、缺口匹配和裁决按评分规则执行。泛泛的专业关联提醒及安全测试条目不能自动作为顾问缺口。

## 3. 数据复核与正式冻结

1. 两位评分者对6例开发数据独立试标，记录拆分和判断分歧，再定稿规则。没有第二人时如实说明单人评测。
2. 审核每例实际可见事实、学生确认状态、去重后的具体缺口与有用事实机会，填写 `gold_gaps.csv` 与 `gold_opportunities.csv`。现有56项草稿不直接作为最终缺口分母。
3. 合成候选集可做探索性挑战评测。若要独立 held-out 结论，另备20例由未参与系统开发、未见输出的人独立起草和复核；保留作者与独立性说明，不能将已有案例换名充数。采用五类风险各4例，多经历至少一半；目前合成集全部多经历。
4. 在正式运行前固定样本数、输入、实际问答协议、stage gold、规则、提示、模型参数、代码版本和哈希，填 `run_manifest.json`。不根据正式结果调整同版数据或删除失败案例。

## 4. 主对照实验

`prompt_only` 与 `full_guardrail` 使用相同 JSON CV、目标项目和实际学生回答；模型、生成参数、任务与输出字段相同，均提示仅使用提供的事实。

为测 guardrail 的增量，两组共享一次冻结的上游访谈/解析状态与同一候选生成结果。基线直接交付候选，完整组增加语义核查、确定性引用/归属/确认/数字检查、收窄与二次核查。评分对照原始CV及实际回答，不能把模型解析内容或隐藏回答库当真值。两组得到不同回答的端到端访谈实验只能补充报告，不能冒充 guardrail 单因素对照。

生成匿名素材包、随机顺序并单独保管组别映射；评分者不看内部 verdict/审计。两组相同提取用户可用内容，保留限制与待问问题。两人独立评分后裁决，保留原判和分歧。报告两组总体与逐例指标、五类切片、至少3个原始失败或误判案例；样本太少时报告实际数量，不编造案例。小样本不宣称统计显著。
