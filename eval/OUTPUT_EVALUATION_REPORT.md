# 真实模型输出的AI辅助评分 v1

2026-10-04。已完成20例、两组共40份输出的单一AI评分。原始模型输出、gold和评分规则保持冻结版本。本轮不修改生产代码、不重跑模型，不用模型核查器的verdict当真值。

**结论：完整系统的无依据论点率有所降低，但仍未达到原提案的 <10% 目标；主要缺陷在未经核查的可用叙述，且生成角度仍有误放和误拦。** 本结果来自AI编写的合成数据和AI参考标注，没有独立人工复核、独立held-out或统计显著性结论。

## 1. 数据与评分记录

- 供应商OpenRouter，模型`openai/gpt-4.1-mini`，运行`20261003T183705Z-8d15689b`；两组共享实际逐轮问答、解析状态和同一候选。
- 20例、40份实际交付素材包；标注1265个原子论点、56个缺口判定、112个事实机会判定、40个案例状态。
- 按[评分规则v1](SCORING_RULES.md)检查主线、角度、素材总结叙述及使用说明中的学生事实。原始记录与审计不计已发布论点；同一原句在叙述、专业转译、深挖和要点中重复时合并。真实待问方向和核实请求不计事实。
- Word将`narrative`列在“素材总结”中，另有“已记录事实与来源”栏目；前者会被推荐使用，所以不能仅因它由原记录拼接，就从已发布论点分母排除。
- 每条记录保存匿名ID、经历、输出位置、原始CV/实际回答位置、标签和理由。答案库隐藏内容、解析所得fact和reviewer verdict不作真值。直接转录实际回答的论点也保留原句条件，指令和计划不能变成已完成行动。
- 使用匿名包评分，但评分者也参与实现且可从输出风格推断组别；不能称独立盲评或双人评分。CV在上下文中被间接确认的边界、温和能力概括、原子拆分与同义合并仍需外部校准。引用错误另一个维度，本轮未系统评分，不能报告0错误。

### 为什么两个高分不能单独证明顾问质量

保留率按预先定义的具体事实机会评分；这些原话在两组共同叙述中完整保存，所以两组均为100%。这并不表示模型提供了高质量专业转译：辅助经历20例使用大量重复回答，保留本身很容易；一些有依据的生成概括被guard拦截，但原话仍在。

缺口分母共28项。“detected”可来自可用叙述或深挖中明确保留相应限制，不要求一定新提追问。因此许多命中来自直接保留学生已经说出的限制，不能宣称AI主动发现了23个新缺口。5项只判partial：EVAL06解决方法缺失未明确指出、EVAL07概念不足却被标为运用知识、EVAL10前后端职责、EVAL12个人一等奖、EVAL14留存率效果。后三例有纠正/无证据提醒，却仍发布相冲突或无依据的内容。

## 3. 错误发生在哪里

这是同一套原子标注的栏目拆分，不是改规则后另造指标。

| 栏目 | 基线无依据/全部 | 完整组无依据/全部 |
| --- | --- | --- |
| 共同可用叙述 | 85/543 | 85/543 |
| 主线与角度（含重复使用建议的合并） | 52/128 | 18/51 |
| 合计 | 137/671 | 103/594 |

完整组剩余103条无依据论点中，**85条（82.52%）来自共同叙述**：80条缺乏确认、4条与回答冲突、1条将待做事项升级为已做行为。只核查主线和angle留下了这个出口。

完整组仍有18条无依据主线/角度，包括未确认的兴趣、过强的知识深度和未解释的后端理解。与此同时，已标注为有依据的主线/角度概括计数由76变为33；这不是严格一一匹配的删除数，也不是预设保留率，但提示只看原话保留率会掩盖概括的损失。

## 5. 下一轮改进优先级（本轮没有改代码）

1. **先修可用叙述的事实准入。** `counselor/workflow.py:make_result`保留原始记录供审计，但候选叙述不能无条件拼入全部fact_items。未确认CV职责/工具/成果明确留作待核实；已被学生纠正的记录保留历史来源并退出可用素材。先处理85条共同叙述问题，不需要重做整个证据收集模块。
2. **修答案解析的言语类型与否定。** `counselor/llm.py:parse_experience_answer`及工作流入库检查要求原文证据、范围和状态；区分事实、请求、计划、否定与撤回，防止“请写效果”“尚不了解”“需要先做”升级为成果、已运用知识或已完成行动。
3. **核查最终完整素材包。** `counselor/claim_check.py`与`review_full_brief_claims`扩到所有可用叙述、角度、主线、转译、使用建议和三问策略中的学生断言；`server.py`在组合后的最终结果上执行发布检查，`document.py`导出同一通过检查的结果。不能在受控字段通过后再拼入未经核查文本。
4. **针对误放和误拦校准。** 用EVAL10后端理解、EVAL13深入程度、EVAL14指令转成果及EVAL15局部计时作为已看过的开发回归案例。当前20例已被查看，不能再称下一轮独立held-out；修复后保留本轮结果，另建运行，并准备独立案例与第二评分者。

最终作业报告现在可以引用真实运行、成本、这次评分和实际失败分析。独立人工复核/新数据的证据仍缺，写报告时必须如实列为限制，而不是补写为已完成。
