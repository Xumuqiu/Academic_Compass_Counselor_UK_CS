# 已完成的参考标注：stage_gold_v1

2026-10-04 按用户要求由 Codex 完成，适用于当前26例合成CV及实际规则访谈回放。**数据作者与标注者为同一AI代理；不是独立人工评分，不是独立held-out，也没有真实模型成绩。** 可以据此继续合成挑战评测，无需将它描述为人工gold。

## 查看和使用

- [逐例标注总览](CASE_REVIEW.md)：26份JSON，每条附实际回答原文、轮次、来源位置、可接受范围与检测条件。
- [缺口标注表](gold_gaps.csv)：39个具体缺口，开发集11个、20例候选集28个。
- [有用事实机会表](gold_opportunities.csv)：73项，开发集17项、候选集56项。
- [原参考论点复核](reference_claim_review.json)：复核原104条正/负例，说明仅CV记录或未问答案为什么不足以确认。它们是复合参考示例，实际模型输出仍须按原子论点拆分评分，不能直接把104条算成系统错误率。
- [排除清单](excluded_gaps.json)：26条泛泛的辅助经历专业关联提醒、1条提示注入测试项，共27项不进入主缺口覆盖率分母。提示注入仍须检查，但作为安全行为记录。
- [版本清单](manifest.json)与[快照哈希](checksums.json)：保存原数据、规则和标注脚本的来源哈希；尚未冒充正式运行冻结。

只将CV和当题回答发送给被测系统；本目录的标注不得进入模型上下文。原数据和gold草稿均未覆盖。

## 关键修订

1. 仅引用实际送达的回答，未问到的过程、知识与成果答案不自动确认。
2. 将身份冲突和贡献边界、时间性能与内存、原创性与证明等可分别核查的问题拆开；新增从实际回答可见的具体局限，避免漏标。
3. EVAL08主经历没有足够具体的已确认有用事实，不要求系统把“参加讲座并提交心得”作为确认论点保留；其辅助经历仍有一个核对记录的真实陈述机会。
4. 有用机会共47项来自主经历、26项来自辅助经历。辅助经历的核对资料回答高度重复，专业深度有限；须同时报告主/辅助经历的保留率，避免通用动作使总体保留率显得过高。这批合成数据不能代表真实学生经历分布。
5. 原“可支持”参考例中，只得到部分确认的完整表述记为 `insufficient`；并以本版更窄的事实机会替代。例如EVAL14仅确认修链接，未确认更新日期；EVAL17仅确认处理缺失值，未确认删除重复行。

缺口数量变化不是简单删除：原56项排除27项后，其余条目再核对可见性、拆分并新增具体缺口，形成39项。版本对照以描述和证据为准，不沿用旧编号制造一对一关系。

## 后续评分

每例以本版 `gap_id` 和 `opportunity_id` 匹配匿名输出。两组共用同一分母，主指标只给完全正确的缺口检测计分；原子论点支持关系仍以原始输入为准，gold示例不是措辞白名单。使用已有空白 `claims.csv`、`gaps.csv`、`opportunities.csv` 填系统输出评分。

若真实模型解析使实际问题/回答路径改变，本版分母不能直接照搬；先对共同实际输入重新核对可见证据，并保存新版本或明确记录输入偏离。主实验宜沿用相同固定回放，保证两组收到相同信息。

复现：在项目目录运行 `python3 -m eval.annotate_synthetic_profiles`。脚本重建本目录的标注数据和快照，不调用模型，不更改原测试数据。自动检查只验证编号、位置、原文和文件一致性，不能充当独立语义复核。
