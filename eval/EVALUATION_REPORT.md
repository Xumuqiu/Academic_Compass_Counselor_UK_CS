# UK CS Counselor 阶段评估与成本分析

运行日期：2026-10-03。范围：当前多经历头脑风暴系统，尤其是“已记录事实能否支持论点具体措辞”的 guardrail。方法沿用同学 VSKC 方案启发的冻结真值、同案对照、切片和失败分析纪律；完整评分口径见 [`TEST_PLAN.md`](TEST_PLAN.md)。

## 结论范围

本次**已经完成** 26 项项目自动化测试和 20 例冻结合成挑战集的离线配对实验。**尚未完成**真实模型有效响应、独立作者 held-out、双人盲评或人工成本实测。用户后来说明，本地 `DASHSCOPE_API_KEY` 字段中配置的是 OpenAI 密钥；它不能用于当前只支持 DashScope 的系统。用该值对 OpenAI 官方 Chat Completions 端点进行的一次最小诊断也返回 HTTP 401 `invalid_api_key`。离线核查结果是预设夹具，不能把下面的 80% 称为真实模型准确率或最终课程评估成绩。

## 数据与运行

挑战集由实施者编写，五类各 4 例：充分支持、表述过强、缺失／含糊、引用异常、语言及适用范围。数据哈希为 `d1d7213fd84ad2a3011550c2e31ace35fd54a45a96240be2f959a612b4e42c49`。每例使用相同的 CV、回答、候选论点和引文，对照“仅检查引文存在”与当前完整 guardrail；模拟核查器输出不输入 gold。运行：`python3 -m eval.run_offline`。原始逐例结果见 [`results/offline_outputs.jsonl`](results/offline_outputs.jsonl)，汇总及执行时间见 [`results/offline_metrics.json`](results/offline_metrics.json)。

| 指标 | 仅查逐字引文 | 新 guardrail |
| --- | ---: | ---: |
| 有事实支持的原论点被保留 | 11/11 | 8/11 |
| 不安全原论点被错误放行 | 9/9 | 1/9 |
| 与预设人工标签一致 | 11/20（55%） | 16/20（80%） |
| 20 份 Word 包含论点核查、无学业规划 | 不适用 | 20/20 |

以上样例特意让所有候选论点都带一个存在的引文，因此逐字引文基线会放行全部；这检验“有引文不等于受支持”，**不代表真实用户输入中有 100% 的危险论点**。新 guardrail 的“放行 1/9”也不是模型实测结果。

### 失败案例

- **B04，漏拦：**学生只说修改了页面布局，候选论点却声称通过用户实验显著提升留存率。模拟核查器错误返回 `supported`，引用虽真实，程序仍放行了语义上过强的论点。说明结构校验无法取代可靠的语义判断；真实模型核查及人工抽查是必要环节。
- **D01、D02，过度拦截：**论点本身可由正确经历支持，但模拟核查器引用了其他经历或不存在的事实 ID。程序拒绝错误引用，导致本可使用的论点被挡下。应评估核查器找对出处的能力，并报告安全论点损失。
- **D04，过度拦截：**论点本身有事实支持，但核查器只拆出前半句。代码要求所有片段拼回整句，因此拒绝结果。这是合理的失败关闭策略，代价是可用率下降。

五类切片的离线 guardrail 一致率依次为 4/4、3/4、4/4、1/4、4/4；“引用异常”最弱。20 例和每切片 4 例都很小，不能据此作统计显著性判断。

## 成本分析：实际、估算与增量分开

本次离线运行没有模型请求，**离线阶段的 API 模型费用 ¥0**。随后尝试了 20 个针对固定论点的 DashScope 请求，全部返回 HTTP 401，未取得任何有效模型输出或 token usage；又进行了少量地域诊断以及一次 OpenAI 官方端点诊断，均返回 401。这些失败请求没有可核实的账单数据，**不能将其实际费用记为零**。20 例失败运行记录见 [`results/live_claim_metrics.json`](results/live_claim_metrics.json) 和 [`results/live_claim_outputs.jsonl`](results/live_claim_outputs.jsonl)；它们不是模型质量评分。本地计算时间与人工编写／评审工时也没有货币化。

价格按当前代码使用的北京兼容接口、默认 `qwen3.7-flash`、同步非缓存请求计算。2026-10-03 查验的[阿里云官方模型价格](https://help.aliyun.com/zh/model-studio/qwen3-7-flash)为单次输入不超过 32K token 时：输入 ¥0.2／百万 token，输出 ¥0.8／百万 token。超过 32K 的请求需按更高档单独计算；优惠、免费额度、缓存、税费未纳入。公式是**逐请求** `输入 token × 输入单价 + 输出 token × 输出单价`，再求和。代码见 [`cost.py`](cost.py)。

以下是**假设 token 数的情景估算**，不是模型账单：

| 情景 | 请求构成 | 假设输入／输出 token | 单案例估算 | 20 例估算 |
| --- | --- | ---: | ---: | ---: |
| 结构化 CV，回答 1 轮，不需收窄 | 答案解析 1 + 素材生成 1 + 论点核查 1 | 5,900／2,250 | ¥0.00298 | ¥0.0596 |
| 结构化 CV，回答 8 轮，需收窄后二次核查 | 答案解析 8 + 素材生成 1 + 论点核查 2 | 10,700／4,000 | ¥0.00534 | ¥0.1068 |

在第一种情景中，不含论点核查的答案解析与素材生成约 ¥0.00176／例；首次核查增加约 ¥0.00122／例。一次收窄后二次核查按表中假设再增加约 ¥0.00096／例。若输入 TXT／DOCX／PDF，还需加上简历抽取调用；若重试或输入更长，也会增加费用。为 20 例**固定论点**只测一次核查，按每次 2,500 输入／900 输出 token 估算约 ¥0.0244；这与运行完整流程的费用不能混为一谈。

真实运行脚本 [`run_live.py`](run_live.py) 会逐调用保存供应商返回的输入／输出 token、时延和按价格档计算的费用；供应商未返回 usage 时标为“未知”，不会填零。人力成本需另记录 `标注小时数 × 实际小时单价`，包括准备独立案例、两位评分人盲评、分歧复核和失败分析；当前尚无工时与单价，因此不填估值。

当前脚本和上述人民币估算对应 **DashScope 的 `qwen3.7-flash`**。如果决定将系统和评测一起迁至 OpenAI，需要另做供应商配置与同案重测，不能把现有价格直接套用。供预算比较，2026-10-03 查验的 [OpenAI 官方 `gpt-4.1-mini` 价格](https://developers.openai.com/api/docs/models/gpt-4.1-mini)为每百万输入 token $0.40、输出 token $1.60；按表中同样的假设用量，单案例分别约 $0.00596 和 $0.01068，20 例约 $0.1192 和 $0.2136。这仅是美元计价的情景估算，未做汇率换算，也不是当前系统的账单。

## 下一轮判定

本次离线实验支持一个有限结论：逐项引用和失败关闭能拦住大多数**预设核查结果下**的不安全原论点，但当语义核查器错误地认定“布局修改支持留存率提升”时仍可能漏拦，也会因错误引用或拆分不完整错拒安全论点。真实模型到位后先运行固定论点 `claim` 模式，再运行完整 `full` 模式并盲评素材包。正式质量结论还需要独立的 6 dev + 20 held-out；本挑战集不能重复命名为独立 held-out。
